# File and resource catalog compatibility

| Area | Status | Reference source | Fixture | Notes |
|---|---|---|---|---|
| Explicit-endian binary primitives | compatible | `src/Engine/CatFile.cpp`, `src/Savegame/SaveConverter.cpp` | `binary-endian-primitives` | Bounded readers and writers cover signed and unsigned integers plus IEEE floating point in both byte orders. |
| Resource lookup and layer precedence | compatible | `src/Engine/FileMap.cpp` (`VFSLayer::insert`, `VFSLayerStack::_merge_resources`) | `vfs-layered-catalog` | Lookup is case-insensitive; the last entry in a layer and the highest layer win. |
| Vertical resource slices | compatible | `src/Engine/FileMap.cpp` (`VFSLayerStack::get_slice`) | `vfs-layered-catalog` | Results retain a nullable slot for every layer from lowest to highest priority. |
| Virtual folder unions | compatible | `src/Engine/FileMap.cpp` (`VFSLayer::insert`, `VFSLayerStack::_merge_vdirs`) | `vfs-layered-catalog` | Lists contain immediate resource basenames, exclude rulesets, and are emitted deterministically. |
| Ruleset separation and order | compatible | `src/Engine/FileMap.cpp` (`isRuleset`, `VFSLayerStack::push_back`) | `vfs-layered-catalog` | `.rul` matching is case-insensitive and order follows entries within layers, then layer priority. |
| Installation-wide `common` layer | compatible | `src/Engine/FileMap.cpp` (`FileMap::setup`, `VFS::map_common`, `mapExtResources`) | `CommonResourceLayerTests`; `ModDiscoveryTests` | `common` is mapped once per installation as the load plan's base layer, below every mod, whether or not a master declares `loadResources`; its directory outranks its ZIP. Catalog creation from a discovery result carries the common layers, and combined catalogs require them explicitly. Only a top-level master can declare external resources (`src/Engine/ModInfo.cpp`, `ModInfo::load`), and those layers sit above `common` but below that master's own files. A resource layer is kept only when it maps more than one file, as in `mapZip` and `mapPlainDir` (`mapped_count > 1`); this count precedes case-insensitive key collisions. Embedded `common.zip`/`standard.zip` executable assets do not exist in this port. |
| Filesystem directory layers | compatible for portable virtual paths | `src/Engine/FileMap.cpp` (`ls_r`, `VFSLayer::mapPlainDir`, `canonicalize`), `src/Engine/Unicode.cpp` (`lowerCase`) | `vfs-unicode-canonicalization`; generated directory/ZIP unit fixtures | Recursive physical-file discovery is bounded and deterministic. Reparse points and unsafe or invalid-Unicode virtual paths are rejected. Lookup follows the pinned Windows reference for captured scalar mappings without merging Unicode normalization forms; original relative spelling is retained separately. Host-locale-specific C++ casing differences are deliberately replaced by one documented portable definition. |
| Malformed lookup paths | compatible in compatibility mode | `src/Engine/FileMap.cpp` (`canonicalize`, `at`, `get_slice`) | `VirtualFileCatalogTests` | [ADR 0026](../decisions/0026-input-validation-modes.md): strict mode (default) rejects rooted paths and empty, `.` or `..` segments and normalizes `\` to `/`. `--input-mode=compatibility` treats all of these, including any `\`, as misses like the reference. |
| Text encoding of YAML inputs | compatible with warning | `src/Engine/FileMap.cpp`, `src/Engine/Yaml.cpp` (raw bytes) | `YamlCompatibilityReaderTests`; `InstallationContentLoaderTests` | Invalid UTF-8 rulesets, metadata, name pools and language files are decoded as Windows-1252 and report warning `OXCE-YAML-0001` with the owning mod. The original X-COM data contains no YAML, and the supplied OXCE saves are UTF-8. Four files in the private third-party mod corpus (three `layered-armors_40k.rul`, one `metadata.yml`) use the legacy encoding and warn. |
| ZIP-backed layers and prefixes | compatible | `src/Engine/FileMap.cpp` (`VFSLayer::mapZip`, `mapZipFileRW`) | generated single-/multi-mod ZIP fixtures; generated external-resource ZIP fixtures | Root and prefixed layers are indexed lazily with archive entry provenance. Entry count, path depth/length, compressed size, per-entry expansion, and total expansion are bounded; rooted, traversal, empty-segment, drive, and URI-like paths are rejected. |
